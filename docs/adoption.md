# Adoption: listings, channels and app stores

Where vaultgate can be listed, what each listing needs, and what a submission actually consists
of. Every mechanism below was checked on **2026-09-23**; the "How" column quotes the target's own
instructions and the "Checked" note says what could and could not be confirmed from here. The
maintainer submits; nothing in this repository submits anything automatically.

Legend: **Ready** means the repository already has what the listing needs; **Blocked** names the
condition to wait for.

## App-store definitions to add later

Each of these is a packaging artefact in its own PR. The one-liner says what the store requires;
none of them exists yet. vaultgate needs TLS terminated in front of it, so every definition either
bundles Caddy (as `docker-compose.yml` does) or documents the store's own reverse proxy.

| Store                                                                                                                       | What it needs                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| --------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Unraid Community Applications](https://forums.unraid.net/topic/87144-ca-application-policies-notes-for-template-creators/) | A GitHub "template repository" holding one XML file per app (`<Container version="2">` with `Name`, `Repository` = `ghcr.io/adamrowles1996/vaultgate`, `Registry`, `Support` = a forum thread, `Project`, `Overview`, `WebUI`, and `Config` entries for ports, paths and variables) plus `ca_profile.xml`. Register the repository through the CA maintainers' form linked from that policies thread (allow up to 48 hours); closed-source and unsafe templates are refused outright. Format reference: [selfhosters.net templating guide](https://selfhosters.net/docker/templating/templating/). |
| [Umbrel](https://github.com/getumbrel/umbrel-apps)                                                                          | A PR adding `vaultgate/umbrel-app.yml` and `vaultgate/docker-compose.yml` (the layout every app in that repository uses, e.g. `vaultwarden/`). The repository's `AGENTS.md` points contributors at its `.claude/skills/` (`umbrel-package-app`, `umbrel-test-app`) for the exact rules. A [community app store](https://github.com/getumbrel/umbrel-community-app-store) template exists for self-publishing without the official review.                                                                                                                                                          |
| [CasaOS](https://github.com/IceWhaleTech/CasaOS-AppStore)                                                                   | A PR adding `Apps/vaultgate/docker-compose.yml` with the top-level `x-casaos` block (required: `id`, `main`, `port_map`, `icon`, `title`, `category`; `index` in practice; `tagline`, `description`, `architectures`, `author`, `developer` recommended) and icon, thumbnail and screenshot assets; run `./scripts/build_dist.sh` before opening the PR. Spec: `docs/specs/compose-and-x-casaos.md` in that repository.                                                                                                                                                                            |
| [TrueNAS](https://github.com/truenas/apps)                                                                                  | A PR adding `ix-dev/community/vaultgate/` with `app.yaml` (`train: community`), `ix_values.yaml`, `questions.yaml` and `templates/docker-compose.yaml` (a Jinja2 template using the catalog's library). "All new contributions should target the `community` train." Guide: `CONTRIBUTIONS.md` in that repository.                                                                                                                                                                                                                                                                                 |
| Helm chart                                                                                                                  | A `charts/vaultgate` chart in this repository, released with [helm/chart-releaser-action](https://github.com/helm/chart-releaser-action) to GitHub Pages or pushed as OCI to `ghcr.io`, an `artifacthub-repo.yml` beside the index (or pushed with `oras` under the `artifacthub.io` tag for OCI), then "Add repository" in the [Artifact Hub](https://artifacthub.io/docs/topics/repositories/helm-charts/) control panel.                                                                                                                                                                        |
